# 通过本机客户端下载 XM 或 M4A

下载功能依赖 macOS 商店版喜马拉雅客户端，目前已验证 4.0.13，无需手动导出 Cookie。

脚本临时启动客户端，通过进程管道复用登录态、请求签名和 XM 编码器。默认 3 并发，不使用客户端界面的下载队列，结束后恢复普通启动。

## 使用

需要 Node.js 和已登录的喜马拉雅客户端；测试使用 Node.js 26.13.1。运行前从菜单正常退出喜马拉雅，运行期间不要手动启动或退出客户端。

先试一集：

```sh
node download-xm.cjs 83737266 ./xm-downloads 1
```

下载整个专辑：

```sh
node download-xm.cjs 83737266 ./xm-downloads
```

直接下载 M4A（固定档位 2），以专辑 `47517749` 为例：

```sh
# 先下载一集
node download-xm.cjs 47517749 ./xm-downloads 1 m4a
# 下载整个专辑；0 表示不限集数
node download-xm.cjs 47517749 ./xm-downloads 0 m4a
```

第五个参数控制并发数，取值 **1–10**，默认 **3**；设为 `1` 即串行。示例：

```sh
node download-xm.cjs 47517749 ./xm-downloads 0 m4a 3
```

某集失败后，脚本停止派发新任务，并等待已开始的任务结束。超时或音频下载 HTTP 429、502、503、504 时，关闭临时客户端，分别等待 30、60、120 秒后重启续跑，单次运行最多重启 3 次；其他错误或用尽重启次数后退出。日志会指出具体章节及查询音质、获取签名、获取地址或下载校验阶段。单次最多新下载集数仍由第三个参数限制，不会因并发或自动重启而超量。同一输出目录不要同时启动多个脚本进程。

第四个参数是 `xm` 或 `m4a`，省略时仍输出 XM。M4A 模式原样保存下载的音频，不经过 XM 编码，也不转码；若档位 2 返回非 M4A，则停止并报错，不会仅改扩展名。

两种格式都会查询每集的 `trackQualities`，固定选择 `qualityLevel = 2`（超高）。客户端档位为 0 标准、1 高清、2 超高、3 无损；名称不代表固定码率。若该集不提供档位 2、查询失败、无权限或下载失败，会停止，不自动切换档位。脚本不转码，也不能提升源音频本身的质量。

XM 保存在 `xm-downloads/专辑ID/声音ID.xm`，相邻的 `.xm.json` 记录标题、集号和文件哈希。第三个参数限制本次新增集数，`0` 或省略表示全部。

M4A 对应扩展名为 `.m4a` 和 `.m4a.json`。校验记录同时保存请求档位和当时查询到的全部档位。只有记录为档位 2、策略为 `fixed-2` 或旧版 `highest`、且哈希匹配的文件才会跳过；新记录使用 `fixed-2`。其他档位或缺少有效记录的文件不会覆盖，请核查冲突或使用新输出目录。

权限、签名、验证码、未知格式和文件校验错误会直接停止，不会将失败条目标记为完成。遇到验证码，请在客户端正常完成验证后重新运行。

可以继续用项目现有流程解密这些 XM。脚本不会修改客户端原有下载记录，也不会覆盖其原有 XM。

## 自检

```sh
node download-xm.cjs --self-test
```

自检覆盖管道分帧、M4A 格式检查、重启退避与次数上限、并发调度及失败后的在途任务处理，不执行真实下载。

## 独立下载 M4A

`download-independent.cjs` 启动时临时读取已登录客户端的会话 Cookie、公共请求头和当前实际加载的 SDK，随后关闭客户端。后续签名由隔离 Chrome 执行 SDK，列表、音质、下载地址和音频由外部 Node 进程处理；结束后恢复客户端普通启动。

需要本机 Node.js、已登录的 macOS 商店版喜马拉雅 4.0.13，以及 `/Applications/Google Chrome.app`。运行前正常退出喜马拉雅；执行会中断播放。SDK 会联网发送临时浏览器的指纹及设备信息，Cookie 只发往原服务的对应域名，不进入签名浏览器，也不写入文件或日志。

```sh
# 先下载一集
node download-independent.cjs 61310701 ./xm-downloads 1
# 整张专辑，默认3并发
node download-independent.cjs 61310701 ./xm-downloads
# 最多新增10集，3并发
node download-independent.cjs 61310701 ./xm-downloads 10 3
# 离线自检，不启动客户端或浏览器
node download-independent.cjs --self-test
```

参数为 `专辑ID [输出目录] [最多新下载集数，0表示全部] [并发数1–10]`。仅输出固定档位 2 的 M4A，不转码、不降档，不提供 XM 包装。输出文件和校验记录与 `download-xm.cjs` 的 M4A 模式兼容；同一目录不可同时运行两个入口。有效记录与哈希匹配时跳过，文件或记录冲突时停止并保留原件。

每页重新生成签名。API及音频请求超时、网络错误或 HTTP 429、502、503、504 时，按 30、60、120 秒有限续跑，保留本次新增集数上限；不会重新启动客户端取会话。权限、验证码、空列表、签名失败、未知音质和内容校验错误直接停止。会话过期时，请在客户端正常登录后重新运行；尚未实现独立登录或会话刷新。每集整体读入内存，上限 200 MB。

独立入口已通过 3 并发下载验证：三个样本与客户端下载原件的哈希一致，FFmpeg 全长解码通过，客户端入口可识别这些完成记录并继续下载。离线自检覆盖分页及后续页异常、取消、集数上限、权限错误、续跑和冲突保护；尚未验证独立入口的全专辑长时间运行及会话过期行为。

## 单独运行签名 SDK

```sh
# 显式指定可信的当前 SDK 文件
node sign-xm.cjs /绝对路径/当前SDK.js
node sign-xm.cjs --self-test
```

此入口不启动喜马拉雅、不读取账号资料。省略路径时提取客户端内置 `1.6.9.js`，可能落后于实际动态加载版本；独立下载入口会自动使用客户端当前加载的 SDK。指定 SDK 会在隔离 Chrome 中执行。

`const { getSign } = require('./sign-xm.cjs')` 后，`await getSign(SDK文件路径或Buffer)` 返回 `xm-sign` 请求头。每次调用使用临时 Chrome 配置并在结束后清理，不持久保存设备状态。签名 SDK 依赖浏览器和外部网络服务，不能代替登录会话或账号权限；签名值不要提交 Git。

签名使用的隔离 Chrome 固定直连，不使用系统代理，也不修改系统代理设置或关闭证书校验。

## 已知限制

兼容性验证仅覆盖 macOS 商店版 4.0.13。官网下载版 4.0.15 尚未完成下载验证，其他版本也未确认兼容；请以应用实际版本为准。

依赖 4.0.13 的内部模块编号；客户端升级后需要重新验证。仅使用当前账号获准取得的下载地址，不能代替内容购买或会员权限。

单集在内存中处理，上限 200 MB。并发越高，内存占用越大，也可能触发服务端限流，建议从 3 开始。M4A 的下载验证不代表生成的 XM 已通过客户端播放测试；后者尚未验证。

生成的 XM 使用客户端格式和编码器，但首段固定为 64 KiB，不保证与客户端网络分块生成的文件逐字节相同。回读后的原始音频应完全一致。
