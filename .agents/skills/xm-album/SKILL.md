# 喜马拉雅专辑下载、检查与归档

使用中文交流和记录。仓库脚本保持通用；专辑特有的路径、总集数、篇章分类、编号映射和例外都放在临时 Python 脚本中，不修改仓库代码来迎合某张专辑，不把本机信息提交进仓库。

按用户请求选择下载、完整性检查、标题整理或 ABS 归档，不默认串行执行全部阶段。需要解密归档时直接写入最终 ABS 目录，只保存一份解密音频，保留原始 XM；提供可执行、可续跑的命令。

## 指定专辑下载

用户要求下载时，默认使用仓库根目录的 `download-xm.cjs`；明确要求独立下载 M4A 时，使用现有的 `download-independent.cjs`，不另写下载器。用户只要求本地检查或归档时跳过本节；下载后是否归档依用户任务决定，不自动扩展工作。

先确认专辑 ID、输出目录及 M4A/XM 格式。分享短链接需要解析实际跳转，不把短链编号当专辑 ID；能从上下文判断时不重复询问。需要详细参数或兼容性记录时读取 [客户端下载说明](../../../README-客户端下载.md)。

### 运行条件与命令

- 在仓库根目录执行，需要 Node.js。已实测 macOS 商店版喜马拉雅 4.0.13，安装路径固定为 `/Applications/喜马拉雅.app`；不把官网下载版、不同版本或其他机器描述为已验证兼容。
- 使用客户端已登录账号的正常下载权限，无需导出 Cookie。运行前正常退出客户端；脚本临时以管道模式启动，结束后恢复普通启动。执行会中断当前播放，运行期间不要再手动启动或退出客户端。
- 只准备命令时不退出客户端、不开始下载。用户要求实际执行时，按已授权范围运行；未指定全量下载的试测可先验证一集。

命令形式：

```sh
node download-xm.cjs 专辑ID 输出目录 最多新下载集数 格式 并发数
```

第五个参数控制并发数，范围 1–10，默认 3；设为 1 即串行。建议从 3 开始；失败后停止派发新任务并等待在途任务结束。超时或音频下载 HTTP 429、502、503、504 时，关闭临时客户端，按 30、60、120 秒等待后重启续跑，单次运行最多重启 3 次；其他错误或用尽次数后退出。日志区分具体章节和处理阶段，重启不重置最多新下载集数。同一输出目录不要同时运行多个下载进程。

参数顺序固定：第三个参数 `0` 表示整张专辑；第四个参数为 `m4a` 或 `xm`，省略时为 `xm`。例如以下命令使用专辑 `47517749`，实际任务需替换成用户指定的 ID 和目录：

```sh
# 直接保存 M4A，先测试一集
node download-xm.cjs 47517749 ./xm-downloads 1 m4a
# 直接保存整张专辑的 M4A
node download-xm.cjs 47517749 ./xm-downloads 0 m4a 3
# 下载整张专辑并包装成 XM
node download-xm.cjs 47517749 ./xm-downloads 0 xm
```

### 独立 M4A 下载入口

`node download-independent.cjs 专辑ID [输出目录] [最多新下载集数，0表示全部] [并发数1–10，默认3]`。它自动从临时启动的已登录客户端读取初始会话和当前 SDK，关闭客户端后，由独立 Chrome 签名、外部 Node 下载；完成后恢复客户端普通启动。需要安装 Google Chrome，运行前仍须正常退出客户端。Cookie 仅在内存使用，不输出或落盘；会话过期后在客户端正常登录，再重新运行。只支持固定档位 2 的 M4A；输出目录及记录与原入口兼容，同一目录不要同时运行两个入口。修改后运行 `node download-independent.cjs --self-test`，共享代码变更还需运行原入口自检。

### 音质与格式

两种格式都会查询每集提供的音质列表，固定选择 `qualityLevel = 2` 请求下载：0 标准、1 高清、2 超高、3 无损。若该集不提供档位 2 或该档失败会停止，不自动切换档位；不宣称等同于手机端最高音质，也不把档位名称当成固定码率或无损证明。

- M4A 模式直接保存下载的原始音频，不转码、不经过 XM 编码。档位 2 返回非 M4A 时会报错，不仅改扩展名，也不擅自降档。M4A 是容器，不代表无损；需要判断音质时读取实际编码和码率。
- XM 模式复用客户端编码器生成文件，保存前回读比对原始音频。现有解密归档流程可处理这些 XM。
- M4A 已是音频，不再走 XM 解密流程；用户要求归档时使用已有音频整理能力，按任务选择最终目录，避免无意义的重复副本。

### 输出、续跑与验证

输出为 `输出目录/专辑ID/声音ID.m4a` 或 `.xm`，相邻的 `.json` 包含声音元数据、文件哈希、音频哈希、请求档位及查询到的可用档位。声音 ID 不是播放集号，后续顺序应读取元数据中的 `track.index`、标题及专辑实际结构。

- 重新执行同一命令可续跑：只有记录档位为 2、策略为 `fixed-2` 或旧版 `highest` 且文件哈希匹配才跳过。新记录使用 `fixed-2`。其他档位成果或缺少记录的文件不会自动覆盖；需要新输出目录或先核查冲突，不能删掉旧成果强行续跑。
- 单集整体放入内存，下载上限 200 MB；内存占用随并发数增加。使用脚本的有限并发任务池，不往客户端界面一次添加几百个任务。
- 权限、签名、验证码、未知音质、格式和校验失败均保留错误，不关闭证书验证或绕过验证码；需要用户配合时说明当前具体阻塞；只对已列出的可恢复网络错误有限重启，不对权限或内容校验错误重试。
- 验证样本的实际格式、时长、编码、码率及哈希；对比记录中的请求档位与可用档位。单集测试不能代替全专辑完整性验证；原样保存与哈希一致也不等同于全长解码或人工试听。
- 修改下载脚本后运行 `node download-xm.cjs --self-test`；只编辑技能说明不必重新下载音频。

## 直接下载 M4A 后整理

用户要求“下载并整理”“下载后放入 ABS”时，走本节，再按后文的专辑结构、标题清理和归档规则执行。仅下载时交付原始 M4A 与校验记录，不额外归档。已有 M4A 时从文件检查开始，不重新下载、不生成 XM、不解密、不转码。

### 从下载记录建立整理计划

1. 将每个 `声音ID.m4a` 与其 `声音ID.m4a.json` 配对，验证文件 SHA-256 与记录中的 `sha256` 一致；缺少记录、无法解析或校验不一致的条目列为待处理，不凭非零大小认定下载成功。现有命名音频没有下载记录时，可检查标签和标题建立身份，但不能声称已验证下载原始哈希。
2. 从记录的 `track` 读取 `trackId`、`albumId`、`albumTitle`、`title`、`index`、`anchorName` 等实际存在的字段；内嵌标签可能缺失，不能只靠标签恢复标题和顺序。检查专辑与声音 ID 是否匹配，结合 `index`、标题集号和篇章身份确定播放顺序，冲突时列出差异。
3. **不要把 ID 文件名交给 `episode_number` 或直接运行 `organize(raw_directory, ...)`。** `400097657.m4a` 会被数字文件名规则误认为第 400097657 集。先建立“声音 ID → 篇章、原集号、播放顺序、清理后标题、目标路径”的完整映射，再检查缺集、重复、冲突和边界。
4. 生成并检查全量计划后，在临时 Python 中复用 `tagged_audio`、安全路径和原子写入函数，按映射生成最终文件；无需为了适配 ID 文件名先复制出一套中间命名目录。`tagged_audio` 只处理专辑、碟号和曲目号，清理后的内嵌标题及需要补充的作者等标签须在临时脚本中另行设置，不假定通用函数已完成。

### 保持下载与整理的续跑记录各自有效

当前下载器固定按 `声音ID.m4a` 和相邻 JSON 查找完成项，不识别 ABS 路径。为保留下载续跑能力，整理时保留下载源及原始 JSON，在独立最终目录写入带标签的成果；需要预留两份音频及单文件临时写入空间。这两份有明确用途，不另外保留解密或重命名中间副本。

用户明确只保留一份音频或要求原地整理时，先说明当前下载器的路径限制，按后文迁移流程准备恢复记录；不能声称移动、改标签后原下载命令仍会跳过。未解决迁移后的下载续跑前，不自动移动或删除源文件。下载任务尚未结束时，不改写其文件和记录。

- 原始下载 JSON 保持不变。改标签后整文件哈希会变化，不能直接沿用它的 `sha256` 或把改标签后的整文件哈希当作原下载音频哈希。
- 最终目录的 `.progress/` 单独记录声音 ID、源哈希、映射或布局身份、目标路径与目标哈希。跳过整理成果前验证目标内容；更改标题规则或分碟规则时重新核查，不能只看文件存在。
- 比较改标签前后所有 M4A `mdat` 音频载荷的哈希，确认没有转码或改变音频；全量归档按后文要求做 FFmpeg 全长解码。下载哈希匹配、载荷一致和全长解码分别记录，不相互代替。
- 交付下载与归档两个目录、实际完成数、缺集或异常、音质实测结果及各自续跑命令；未执行的阶段明确标注。归档结束不自动删除源文件或同步 NAS。

## 先理解专辑

读取用户指定目录，统计文件格式、数量、大小、目录层级及命名样本；必要时读取 XM 的 ID3 标题，比较标签与文件名。

- 正文、番外、序章、预告、花絮和不同演播版本可能独立编号。同号不一定重复，不能自动丢弃。
- 分卷可能重新编号，也可能沿用全书编号。明确“篇章或版本 + 卷 + 集号”的身份后，再检查重复与缺集。
- 0 集、中文数字、上下集、跳号、不从 1 起始需要按实际证据映射。无法判定的文件列出问题，不静默忽略以通过校验。
- XM 的 `TRCK` / `XMInfo.tracknumber` 是解密所需的声音标识，不是可靠的播放集号；不能篡改它来控制排序。
- 本地集号连续不证明下载完整。对照用户给出的总数或专辑清单确认末集；没有依据时标注“末尾完整性未确认”，不以本地最大集号推断平台总数。

能从文件和上下文判断的规则自行决定；篇章身份或顺序确有歧义时汇总一个简短问题。用户只要命令时，准备和检查脚本后交付命令，不开始长时间全量执行。

## 临时脚本与通用函数

先核对实际接口，按需复用：

| 位置 | 可复用能力 |
| --- | --- |
| `main.py:get_xm_info`、`xm_decrypt` | 读取元数据及解密到内存 |
| `main.py:decrypt_xm_file` | 常规标题编号可直接归档，支持 `book`、`group_size` 和进度记录 |
| `main.py:safe_output_path`、`replace_invalid_chars`、`atomic_write` | 输出路径约束、名称清理、原子写入与冲突保护 |
| `organize.py:episode_number`、`tagged_audio` | 常规集号解析、专辑与碟号及曲目标签 |
| `archive.py` | 可参考现有流程，但其正文/番外分类及从 1 连续编号假设并非所有专辑通用 |
| `organize.py:organize` | 文件名已含可靠集号的普通音频复制整理；不直接处理声音 ID 文件名，新 XM 任务不走这条双份落盘流程 |

将临时脚本放在系统临时目录的独立任务目录，例如 `/private/tmp/xm-album-<任务标识>/run.py`。专辑规则、检查结果和临时日志可放同目录；正式归档与续跑记录存放在用户指定的持久输出目录。

- 常规编号满足现有接口时，临时脚本分组后调用 `decrypt_xm_file`，直接写入最终归档目录。
- 特殊编号不满足高层接口时，临时脚本用 `xm_decrypt`、`tagged_audio`、安全路径及原子写入等底层通用函数组合完成；自行处理实际需要的标题、作者和输出标签。不要强行套用高层接口，不覆盖原函数、不改写源文件标签。
- 只写本张专辑需要的处理逻辑，不建设新的框架或复制整个解密实现。
- 若发现真正的通用代码缺陷，向用户报告，独立处理；不要以适配专辑为由给仓库增加硬编码分支。

临时脚本在仓库根目录通过 `PYTHONPATH` 导入项目，复用 uv 环境：

```bash
PYTHONPATH="$PWD" uv run python -u /private/tmp/xm-album-<任务标识>/run.py
```

交付时用实际路径替换占位符。原始目录路径以 Python 的 Path 或参数传递，避免把文件名拼成 shell 命令。临时目录可能被系统清理；长任务和用户自行执行期间保留脚本，需要时可按技能重新生成，不把正式成果放进临时目录。

## 归档与安全约束

默认直接归档到项目 `output/`，不再生成另一份解密目录；用户指定的路径优先。一本书连续播放，每 200 集一碟，篇章划分和组大小依专辑与用户需求确定，不强制区分正文和番外。

```text
output/
├── 书名（正文）/
│   ├── CD 1/
│   └── CD 2/
└── 书名（番外）/
    └── CD 1/
```

- ABS 碟目录使用 `CD N` 或 `Disc N`，不直接以 `1-200集` 替代。只有用户希望分卷独立展示并记录进度时，才采用系列/分卷布局。
- 常规编号采用 `disc = (episode - 1) // group_size + 1`、`track = (episode - 1) % group_size + 1`。特殊篇章明确映射，保留原集号与标题便于追溯。同步最终文件名、专辑标签、碟号和曲目号。
- 需要确认 ABS 规则时查阅 [官方目录说明](https://audiobookshelf.org/docs/documentation/libraries/book-library/directory-structure/)，符合目录规则不代表完成实际导入验证。
- 解密与标签处理在内存完成，只保存最终归档音频；同目录临时文件仅用于原子发布，不保留解密中间副本。
- 保留路径边界检查及冲突保护。不同内容的同名文件报错，不覆盖；原始 XM、旧成果及本机配置不自动删除或改名。
- 跳过已完成文件前校验输出内容。自建进度时，身份包含源文件内容和影响输出的布局参数或映射版本；记录在最终输出目录，原子更新。中断后能继续，不以文件存在或非零大小判断完成。
- 开始前估算空间：原 XM 之外只需一份归档音频及处理当前文件的临时空间。使用 uv、标准库、Mutagen 和 FFmpeg，不复活旧 `venv39`。

## 章节标题清理

归档前检查标题样本及括号内容，制定本专辑的清理规则，放在临时 Python 中；用户要求清理已有归档时使用同一流程。不要把某张专辑的广告词或书名写入仓库函数。

- 删除已确认的重复书名前缀、订阅评分提示、其他书籍推广、主播更新通知。不要删除所有括号内容：上下篇、版本、人物信息和 `(1)` 等可能属于章节内容，无法确认时保留。
- 保留原集号、章节正文、续集数字与标点。按篇章范围统一集号补零，内嵌标题可用“第0001集 章节名”；文件名保留用于 ABS 排序的 CD / 曲目号前缀。
- 同时更新文件名和音频内嵌标题；保留专辑、碟号、曲目号、作者等其他标签及音频编码。新归档在内存中完成清理后一次写入，不先保存脏标题再生成第二份副本。
- 全量修改前生成旧路径、原标题、新路径和新标题映射，检查目标路径边界、空标题、集号丢失和名称冲突；未知冲突报错，不覆盖。

已有归档的迁移：

1. 将映射与操作进度持久保存到输出目录的 `.progress/`，每条迁移记录源校验值和状态。先准备可重跑的迁移流程，再批量修改，不仅依靠临时脚本保存恢复信息。
2. 原子写入新结果，验证内容后更新所有关联续跑记录的路径和 SHA-256，最后删除对应旧文件。中断后根据迁移记录和校验值恢复，避免旧记录指向已删除文件；不删除与本次映射无关的音频。
3. 检查音频标签及全部关联续跑路径、校验值，重复执行不再次产生文件。布局或清理规则变化时同步检查进度身份，不能让旧记录把任务跳过到错误结果。
4. 标题编辑不转码。对支持的容器可比较清理前后的音频载荷（如 M4A 的全部 `mdat` 数据）哈希，证明音频未变。只有载荷一致且原内容确有全长校验记录，才可迁移该验证记录，并注明依据；否则重新全长解码。元数据变更后不能直接沿用旧整文件哈希。

如果已有 NAS 副本或已导入 ABS，说明本地重命名不会自动同步远端，普通 rsync 会留下旧名称文件，ABS 重新扫描也可能影响进度。仅在用户要求时处理远端同步，不擅自执行删除或添加 `--delete`。

## 检查与交付

临时脚本中为本次规则增加少量 assert 或自检，覆盖真实命名、篇章独立编号、分组边界和歧义。先检查全目录的计划，确认每个文件都有明确去向，输出路径无冲突，再写入音频。

选择正文、特殊篇章和分组边界样本，在独立临时测试目录验证：直接归档、标签、重复运行跳过、冲突不覆盖及仅生成一份音频。没有真实边界样本时用测试夹具补充，不伪造真实结果。

全量任务按来源检查：XM 检查头部和解密结果；直接下载的 M4A 检查配套记录、源哈希与标签修改前后的载荷。两者都检查分组数量，并使用 FFmpeg 全长解码校验归档音频；失败明确退出并保留已完成成果。用户执行时提供相应阶段可直接运行的命令，保留进度显示和续跑能力，不交付长篇 heredoc。

最终报告篇章数量、缺集及重复结论、输出位置、命令、续跑和空间要求。区分文件统计、头部读取、全长解码、人工试听及 ABS 导入的验证范围。只清理自己创建且已不再需要的测试文件；不提前删除交给用户运行或续跑的任务脚本。不自动执行 Git 提交。
